## What boot 5 found instead: no leader chord works from a USB keyboard

`scancodes=147 chords=0`. The operator reached a guest with the `focus` command and had
no way back out.

`hype_chord_feed_scancode()` sets `right_ctrl_held` / `right_alt_held` only from the
EXTENDED forms `E0 1D` and `E0 38`, and every chord needs both. The USB path emitted bare
0x1D and 0x38, folded onto the left-hand codes. No chord could ever fire. Arrows were
un-prefixed too, so they did nothing in hype's own line editor either -- un-prefixed 0x48
is the keypad, and `core/kbd_decode.c` only maps arrows behind the prefix.

Fixed in `a6ad16c`: the USB path emits real Set-1. Right Shift stays single-byte, because
on Set-1 it genuinely is.

**"The keyboard froze when the VM froze" was this, not a freeze.** Input kept flowing for
the whole minute after the guest wedged on `reboot` at t=190.5s -- reports 130 -> 151 and
scancodes 129 -> 147 by t=248s, a steady ~90 polls/sec. What was lost was the way OUT:
focus was on a dead guest, every keystroke went to it, and Right-Ctrl+Right-Alt+Esc could
not be assembled. The wedge itself is #735 and still has no fix.

### If a chord does nothing, the log now says why

The chord needs the **right-hand** Ctrl and Alt specifically. This board has a right Ctrl
and an **AltGr**. On an ISO layout AltGr *should* report as usage 0xE6 -- modifier bit 6,
Right Alt -- but a programmable board can map it to anything, and Fn is normally resolved
inside the keyboard and never reaches USB at all. So this build measures it instead of
assuming:

```
LC_ALL=C grep -a -E 'modseen|chord key seen' \HYPE.LOG
```

```
fw-1 DIAG: HID modseen=0x50 -- RCtrl(bit4)=YES RAlt(bit6)=YES LCtrl=never LAlt=never
```

`modseen` is the OR of every modifier byte the keyboard has reported. **`RAlt(bit6)=never`
after holding AltGr means AltGr is not Right Alt on this board**, and the chord cannot be
typed at all -- which becomes its own ticket, and the answer is a configurable leader.

The second line only appears when a chord KEY arrived with one half of the leader held and
the other missing, and it names the half that WAS there:

```
fw-1 DIAG: chord key seen 4 time(s) with only Right-Ctrl held -- the other half of the
leader never arrived
```

Both counters at zero after trying the chords means the chord key itself never reached
hype -- a different fault from missing modifiers, and this is what tells them apart.
